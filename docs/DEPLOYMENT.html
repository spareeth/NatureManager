Putting Nature OS on a test server

One Linux server with Docker runs everything: the database and sign-in (self-hosted Supabase), the web app, the species identify service, and Caddy for HTTPS. Follow the steps in order. Replace nature.example.org with your own names throughout.

1What you need

ItemNotes
A Linux serverUbuntu 24.04, 4 vCPU, 8 GB RAM (16 GB if the species model runs there), 80 GB disk. A Hetzner CX42 or CPX41 is enough.
Three DNS namesnature.example.org (app), api.nature.example.org (database and sign-in), ai.nature.example.org (species identify), all pointing to the server.
An email account (SMTP)Sign-in is by emailed link, so the server must send email: Microsoft 365, SendGrid, Amazon SES or similar. Without it nobody can sign in.
Files from your PCdata/hortis/raw/2026-04-27/ (Hortis export) and apps/web/public/tiles/ (map layers, about 80 MB). Both are kept out of git.
Optional keysGoogle Map Tiles API key (Google satellite; restrict it to your app domain), Pl@ntNet API key (plant identification).

Open only ports 22 (SSH), 80 and 443 on the server firewall.

2Prepare the server

server, as a sudo user
sudo apt update && sudo apt -y upgrade
sudo apt -y install git curl postgresql-client python3 python3-venv
curl -fsSL https://deb.nodesource.com/setup_22.x | sudo -E bash - && sudo apt -y install nodejs
curl -fsSL https://get.docker.com | sudo sh
sudo usermod -aG docker $USER      # then log out and in again
sudo ufw allow OpenSSH && sudo ufw allow 80 && sudo ufw allow 443 && sudo ufw enable

Install Caddy from its apt repository: caddyserver.com/docs/install.

server
git clone git@github.com:spareeth/NatureManager.git ~/terragarden_platform
cd ~/terragarden_platform && git checkout phase-3

The repository is private: add the server's SSH key to GitHub (Settings, SSH keys) or use a deploy key first.

3Database and sign-in (self-hosted Supabase)

Follow Supabase's Docker guide, supabase.com/docs/guides/self-hosting/docker. In short:

server
git clone --depth 1 https://github.com/supabase/supabase ~/supabase
mkdir -p ~/supabase-project && cp -rf ~/supabase/docker/* ~/supabase-project
cp ~/supabase/docker/.env.example ~/supabase-project/.env
cd ~/supabase-project

Edit ~/supabase-project/.env

SettingValue
POSTGRES_PASSWORD, JWT_SECRET, DASHBOARD_PASSWORDNew strong values. The Supabase guide shows how to generate the JWT secret and the matching ANON_KEY and SERVICE_ROLE_KEY.
SITE_URLhttps://nature.example.org
ADDITIONAL_REDIRECT_URLShttps://nature.example.org/**
API_EXTERNAL_URL, SUPABASE_PUBLIC_URLhttps://api.nature.example.org
SMTP_*Your email account: host, port, user, password, admin email; sender name Nature OS.
ENABLE_EMAIL_SIGNUPtrue (needed for emailed sign-in links)
DISABLE_SIGNUPtrue: only people you add in step 6 can sign in

In docker-compose.yml, set the database image to the Postgres 17 image used in development, supabase/postgres:17.6.1.171 or a later 17.x.

server, in ~/supabase-project
docker compose pull && docker compose up -d
docker compose ps      # all healthy; the database container is usually "supabase-db"

Studio (the database dashboard) is reachable on the API address. Keep it behind its dashboard password, or block it in Caddy and reach it through an SSH tunnel.

4Schema, seed and Hortis data

The commands below need the database port. Expose 5432 to localhost only in the Supabase compose file, or run them from your PC through an SSH tunnel (ssh -L 54329:localhost:5432 server).

server, in ~/terragarden_platform
export PSQL="docker exec -i supabase-db psql -U postgres -d postgres"

# 4.1 All migrations, in order; recorded so later updates apply only new ones
npx supabase@2 db push --db-url "postgresql://postgres:<POSTGRES_PASSWORD>@localhost:5432/postgres"

# 4.2 Terra, the site, asset types and the 48 beds (no demo users)
scripts/deploy/seed_server.sh

# 4.3 Hortis: 77 taxa, 77 accessions, 666 plants (copy data/hortis/raw/2026-04-27/ first)
python3 -m venv ~/.venv-hortis && ~/.venv-hortis/bin/pip install pg8000
DATABASE_URL=postgresql://postgres:<POSTGRES_PASSWORD>@localhost:5432/postgres \
  ~/.venv-hortis/bin/python scripts/hortis/migrate.py --org terra

# check: 666
$PSQL -qAt -c "select count(*) from asset"

Later updates: git pull, then the same db push; it applies only what the server does not have. Never edit a migration that is already on the server.

5Web app

Build on your PC (or on the server with Node 22) with the server addresses. Create .env.server in the repository root; it is kept out of git, so never commit keys.

.env.server
VITE_SUPABASE_URL=https://api.nature.example.org
VITE_SUPABASE_ANON_KEY=<ANON_KEY from step 3>
VITE_AI_SERVICE_URL=https://ai.nature.example.org
VITE_PUBLIC_BASE_URL=https://nature.example.org
VITE_GOOGLE_MAPS_API_KEY=<optional>
your PC, in the repository
cp .env.server .env.production.local      # Vite reads it for the production build
npm ci && npm run build -w @terragarden/web
rm .env.production.local
rsync -a apps/web/dist/ server:/srv/terragarden/web/
rsync -a apps/web/public/tiles/ server:/srv/terragarden/web/tiles/

QR labels print the address in VITE_PUBLIC_BASE_URL. Set it to the real address before printing any label for a tree.

# Satellite overlays, base maps (CAD plan, Dec 2025 image), per-bed values, tree loss.

7Species identify service and HTTPS

server, in ~/terragarden_platform
export APP_DOMAIN=nature.example.org API_DOMAIN=api.nature.example.org AI_DOMAIN=ai.nature.example.org
export ANON_KEY=<ANON_KEY> PLANTNET_API_KEY=<optional>
docker compose -f deploy/ai.compose.yml up -d --build    # first build downloads about 2.5 GB
curl -s localhost:8088/health                            # {"status":"ok",...}

sudo cp deploy/Caddyfile /etc/caddy/Caddyfile
sudo sed -i "s/app.example.org/$APP_DOMAIN/; s/api.example.org/$API_DOMAIN/; s/ai.example.org/$AI_DOMAIN/" /etc/caddy/Caddyfile
sudo mkdir -p /srv/terragarden/web && sudo chown -R $USER /srv/terragarden
sudo systemctl reload caddy      # HTTPS certificates are issued automatically

The identify service needs about 3 GB of memory for the BioCLIP model. On a small server, leave it out: the app still works, and Identify species reports that the service did not answer.

8Check it works

  1. Open https://nature.example.org: the sign-in page loads over HTTPS.
  2. Sign in as the manager you added: the email arrives, and the link opens the map with 48 beds and 666 plants.
  3. More, Biodiversity and Water: figures and maps load; switch the overlay and the base map; try Compare with.
  4. On a phone: add the app to the home screen, sign in as a green team member, open My day, Observe a plant with a photo, Identify species, Save. In flight mode, save another; back online, the bar shows it sent.
  5. Work orders: report a problem from the map; as manager, schedule it; as the green team member, start and complete it; as field manager, verify it.
  6. Print a QR label from an asset page and scan it with the phone camera: the asset opens.
  7. Preventive jobs are generated every night at 00:30 Dubai time; the next morning, Planning shows new jobs.

Daily backup

server, crontab -e
30 2 * * * docker exec supabase-db pg_dump -U postgres -Fc postgres > ~/backups/nature_$(date +\%F).dump

Copy the dumps off the server regularly.

9Known limits of this test build

  • For testing only: one server, no high availability, backups as above.
  • The main web bundle is 1.6 MB (475 kB compressed), so the first load on a weak phone connection takes a few seconds.
  • react-router 6 has a moderate advisory (open redirect through a backslash in links). The app builds its own links, so exposure is low; upgrade to version 7 later.
  • Members cannot be added in the app yet; use scripts/deploy/add_member.sh.
  • Map layer files in /tiles/ can be read by anyone who knows their address. Serve them behind sign-in for production.
  • Vegetation change and tree loss are exploratory research layers; read their notes before quoting figures.
  • Not built yet: Darwin Core export (task 3.7), camera traps (3.8), sensors and alerts (Phase 4).
